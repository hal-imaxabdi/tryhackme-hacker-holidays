DOOR 12 Forensics Medium

After Hours

Summary

An investigation was conducted on an offline Windows Management Instrumentation (WMI) repository file (OBJECTS.DATA). Analysis revealed a malicious embedded .NET binary stored within the ConfigData property of the Win32_HardwareTelemetry WMI class. Upon extraction and reverse engineering of the payload, a hidden password string set during a net user persistence mechanism was decoded to reveal the flag.

Methodology & Execution

Phase 1: Identifying Embedded Binary in WMI Repository

Initial extraction attempts using string grep pipelines failed due to binary fragmentation across continuous Base64 blocks in OBJECTS.DATA.

To reliably extract the payload, a custom Python script was executed to scan the binary OBJECTS.DATA file, identify continuous Base64 blocks, and attempt Deflate stream decompression.

Script Executed:

Python
import re, base64, zlib

with open("OBJECTS.DATA", "rb") as f:

data = f.read()

b64_pattern = re.compile(br"[A-Za-z0-9+/=]{100,}")

for match in b64_pattern.finditer(data):

b64_bytes = match.group(0)

try:

raw = base64.b64decode(b64_bytes)

# Try raw deflate decompression

decompressed = None

for wbits in [-15, 15, 31]:

try:

decompressed = zlib.decompress(raw, wbits)

break

except zlib.error:

continue

if decompressed and (b"BSJB" in decompressed or b"MZ" in decompressed[:2]):

print(f"[+] Found valid decompressed .NET binary ({len(decompressed)} bytes)!")

with open("extracted_payload.exe", "wb") as out:

out.write(decompressed)

except Exception:

continue

Outcome: Successfully extracted and reconstituted the raw executable file as extracted_payload.exe.

📷 [SCREENSHOT PLACEHOLDER 1: Terminal output showing Python script finding the valid .NET binary and saving extracted_payload.exe]

Phase 2: Analyzing the Extracted .NET Payload

Running standard ASCII strings against extracted_payload.exe indicated the binary was a compiled .NET application (updates.exe) containing references to system calls like get_MachineName, ProcessStartInfo, and cmd.exe.

Bash

strings -n 6 extracted_payload.exe

📷 [SCREENSHOT PLACEHOLDER 2: Terminal showing strings -n 6 output with .NET references like mscorlib, get_MachineName, and updates.exe]

Because standard ASCII inspection did not directly output a readable flag, a specialized UTF-16LE string extraction was performed using Python to read C# UTF-16 unicode string literals embedded inside the assembly.

Script Executed:

Python
import re

with open("extracted_payload.exe", "rb") as f:

content = f.read()

# Match UTF-16 Little Endian string sequences
utf16_strings = re.findall(b"(?:[\x20-\x7E]\x00){4,}", content)

for s in utf16_strings:

try:

print("  ->", s.decode("utf-16le"))

except Exception:

pass

📷 [SCREENSHOT PLACEHOLDER 3: Terminal output showing the extracted UTF-16 strings, including the cmd.exe command line string]

Output Findings:

Plaintext

-> bytelotusdc

-> cmd.exe

-> /c net user patch VEhNe1A0dGNoX29wM25lZF90aDNfQmFjS2QwMHJ9 /add

-> Execution halted: Environment mismatch.

The malware attempts to add a local backdoor user named patch with a Base64-encoded password: VEhNe1A0dGNoX29wM25lZF90aDNfQmFjS2QwMHJ9

Phase 3: Decoding the Flag

Decoding the password string parameter via base64 yielded the final challenge flag:

Bash

echo "VEhNe1A0dGNoX29wM25lZF90aDNfQmFjS2QwMHJ9" | base64 -d

📷 [SCREENSHOT PLACEHOLDER 4: Terminal executing echo ... | base64 -d and outputting the final flag]

Flag Output:

Plaintext

THM{P4tch_op3ned_th3_BacKd00r}

Key Takeaways

  1. WMI Persistence: Threat actors can hide payload binaries inside non-standard WMI classes (e.g., Win32_HardwareTelemetry) using Base64 and Deflate compression to evade basic string detection.
  2. Encoding Awareness: .NET applications store string constants using UTF-16LE encoding by default. Standard ASCII string tools will fail to render these strings unless configured for 16-bit wide characters (-e l) or parsed programmatically
